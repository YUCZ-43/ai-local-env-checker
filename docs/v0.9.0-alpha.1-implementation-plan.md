# v0.9.0-alpha.1 Product UI and Website Preview Plan

## 1. Why the current UI still feels generic

The existing desktop UI already has rounded panels, light/dark theme support, and approval screens, but it still reads like a safety dashboard with separate cards. The product identity, platform story, command approval journey, and website-facing narrative need to feel more like a premium open-source AI infrastructure product.

## 2. Target product style

The target direction is calm technical infrastructure: glacier blue, electric blue, frost gray, deep graphite, crisp white surfaces, subtle archive/oracle motifs, and low-motion fluid light. It should be futuristic without cyberpunk clutter and safety-first without becoming a plain enterprise admin UI.

## 3. Desktop UI redesign areas

Improve the dashboard identity, sidebar, environment check, tool catalog, install plan viewer, risk review, admin permission review, real installer approval, command approval timeline, rollback, dry-run controls, controlled run review, execution progress, logs, reports, and settings.

## 4. Website preview structure

Create a static `website/` preview with hero, product UI preview block, platform cards, feature coverage, safety-first section, workflow section, GitHub/docs links, roadmap, and alpha release status. The page must be static, dependency-free, GitHub Pages friendly, and Vercel/Cloudflare preview friendly.

## 5. Design tokens

Use a shared visual language: ice-white and frost-gray backgrounds, glacier-blue/electric-blue accents, graphite dark mode, strong borders, controlled glow, 18-24px radii for premium product panels, compact chips, and monospace command surfaces.

## 6. Motion system

Use medium-low CSS-only breathing motion, subtle background gradients, card hover lift, animated status chips, and active segmented controls. Respect `prefers-reduced-motion`.

## 7. Theme and language system

Keep active desktop controls for Light, Dark, and System themes. Keep active language controls to English and Simplified Chinese only. Preserve existing locale files, including Traditional Chinese, but hide Traditional Chinese from active controls for this alpha.

## 8. Alpha release user journey

The user journey is: review product dashboard, inspect environment/tool status, load an install plan, review risk/admin/command/rollback gates, run validate/simulate/dry-run only, inspect logs/reports, then manually review the generated Windows alpha package if local packaging succeeds.

## 9. Risks

The main risks are overclaiming platform packages, accidentally staging generated artifacts, implying real third-party installation is enabled, hiding approval blockers behind polish, and shipping a website that suggests stable release readiness. Validation must scan for forbidden local paths and fixed proxy ports before release operations.
