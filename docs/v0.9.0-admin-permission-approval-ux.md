# v0.9.0 Admin Permission Approval UX

v0.9.0-alpha.1 is a local self-test and prerelease preparation milestone for the desktop approval layer. It turns the GUI into a product-grade safety-first approval cockpit for reviewing admin permission, command risk, rollback coverage, dry-run state, and audit/report visibility before any future controlled installation path is considered.

This version enables:

- Premium rounded desktop UI with light and dark themes.
- Glacier-blue light mode with subtle CSS fluid motion.
- Graphite and electric-blue dark mode.
- UI-level language selector with active controls for English and Simplified Chinese.
- macOS-style rounded segmented controls for theme and language.
- Stronger product identity, sidebar signal, platform cards, GitHub/docs entry points, command approval timeline, and report/audit preview cards.
- Admin permission review screen.
- Real installer approval screen with real execution disabled.
- Command-level approval screen.
- Rollback strategy screen.
- Dry-run, simulate, logs, reports, and execution-progress structure.
- Static product website preview under `website/`.
- Dependency-free software and website review previews under `preview/`.

This version intentionally keeps disabled:

- Real third-party installation.
- Silent installation.
- Automatic UAC elevation.
- PATH modification.
- Proxy modification.
- Global environment modification.
- Real installer command execution from the desktop UI.

Admin permission is sensitive because it can change machine-wide state, install services, write protected directories, modify global configuration, and create support risk if the operator does not understand the command. The UI must show why admin is required, what command requested it, and why it is blocked or not yet approved.

Dry-run and simulation are review states. They can validate structure, show command previews, and produce local reports. Real execution is a separate state and remains unavailable in this milestone.

The website preview is static HTML/CSS/JS and does not include analytics, remote tracking, remote scripts, heavy dependencies, production deployment, DNS changes, or custom-domain binding. GitHub Pages is the preferred temporary preview route; Vercel and Cloudflare Pages can be used for preview deployment after owner confirmation.

Windows is the only package target for `v0.9.0-alpha.1`. macOS and Linux packages are planned but must not be claimed as available until validated artifacts exist.
